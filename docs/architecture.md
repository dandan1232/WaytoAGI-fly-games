# 技术架构 v1

## 决策

采用 TypeScript + Vite + Canvas 2D。UI 用原生 HTML/CSS，游戏在单画布内绘制。首版是 2D 纵向物理跑酷，Canvas 2D 足以支撑建筑、角色、清洁遮罩、粒子和镜头缩放，并保持包体小、手机启动快。无需后端和外部资源请求，Vercel 提供静态托管。

## 模块

```text
src/main.ts         DOM、流程状态、输入/渲染接线、生命周期
src/core.ts         纯物理与任务状态；无 DOM、Canvas、音频依赖
src/level.ts        关卡尺寸、平台、障碍、住户、泥团的类型化数据
src/render.ts       原创画面、摄像机、清洁遮罩、结局拉远
src/input.ts        鼠标/键盘/虚拟摇杆归一化输入
src/audio.ts        Web Audio 合成水流和提示音，用户操作后初始化
src/storage.ts      版本化最佳成绩存取、无效数据及存储失败回退
src/style.css       首屏、HUD、触控、暂停及结果面板
tests/             纯逻辑回归、可达性模拟
scripts/           生产检查与浏览器验收辅助
docs/              需求、架构、验收和部署证据
```

数据流：Input → fixed-step simulation → GameState → Renderer / HUD。渲染不修改物理。存档只在结算时写入。核心逻辑可在 Node 中独立运行，同一关卡数据供实际游戏与模拟可达性验证使用。

## 坐标与时间

世界坐标 x 向右、y 向下；楼底为较大 y，楼顶为较小 y。Canvas 用 CSS 尺寸布局、DPR 上限 2 绘制。鼠标坐标通过画布边界与摄像机逆变换进入世界坐标；触摸摇杆产生单位方向向量。

固定 1/120 秒物理子步，帧间时间夹紧至 0.1 秒，每帧最大 12 步。速度用阻尼/加速度及速度上限限制。重力始终向下，喷水推力等于喷射单位向量的反方向乘推力常量。水量耗尽立即停止推力和清洁。

## 状态与关卡

应用状态：title → playing ↔ paused → victory / rescue。救援是非阻塞的短暂反馈，物理在检查点恢复；victory 锁定输入、开始全楼缩放动画。重玩建立全新 GameState。失焦只在 playing 时暂停，不自动启动音频。

核心模型包含 Player（位置、速度、水量）、Platform（矩形、补水/检查点属性）、Obstacle（矩形）、DirtCell（世界位置、剩余厚度）、Resident（关联窗户范围、解锁状态）、Mud（生命值）、RunMetrics（活动用时、救援数、最高高度）。洁净度是已去除厚度 / 全部初始厚度；住户窗格清洁达到 60% 解锁。最佳记录按星级、洁净度、住户数量、较短用时依次比较。

水束用有限距离线段与多个采样点/污渍网格求交；只清除击中范围，进度由实际清除的污渍总量计算。住户按自身窗格的清洁比例解锁。空调会截断水流，以保持视觉与规则一致。粒子是视觉层对象，不参与判分。

## 碰撞、补水与通关

角色使用轴对齐包围盒。固定子步先更新速度，再分别处理水平与垂直位置，避免平台边缘粘住。补水平台和楼顶从下向上可穿过、下降时可落脚；空调实体四面碰撞。处于平台顶面且速度稳定时补水，站稳后仅向更高处更新检查点。越过底部/远离有效场景触发救援，回最高检查点并补满水；手动和自动救援均计数。

楼顶平台是最终目标，角色落在楼顶触发通关。通关不强迫全楼 100% 清洁：基础一星，清洁度达到 35% 加一星，解锁至少三位住户再加一星。结局先保留实际清洁图案，随后用明确的「焕新画作揭晓」过渡展示完整壁画，不把自动揭晓计入洁净度。

## 视觉与声音

视觉为明亮的漫画建筑剖面：卡赫黄 #FFDA00、墨蓝 #203C4B、天空蓝 #D9EEF3、珊瑚橙 #E78C67、窗绿 #83B9AD、纸白 #FFFDF3。标题粗黑中文无衬线，UI 使用系统字体，数字用等宽字体。记忆点是背着黄色水箱的小人被水流反冲得东倒西歪。

Canvas 绘制矢量建筑、窗内人物、云和艺术壁画；减少依赖并保持任意尺度清晰。水流合成音效默认关闭，显式开启后使用 Web Audio；暂停、失焦和停止喷水时平滑静音。减少动态效果模式限制粒子和镜头晃动。

## 验证与发布

- 单元/模拟测试：反冲方向、无水边界、碰撞、补水、救援、暂停控制、污渍计数、住户解锁、胜利及标准路径通关。
- 类型和构建：`npm run check`、`npm run build`。
- 浏览器：实际输入验证开局升空、清洁进度变化、暂停时间冻结、移动端摇杆、重玩和无控制台异常；截图检查布局和可读性。
- 生产：`vercel deploy --prod`，复用 `.vercel/project.json`，记录 READY 与最终域名，再用匿名浏览器验证。Vercel 配置构建 `npm run build`、输出 `dist`。
- 所有凭据仅由 Git/Vercel 官方认证使用，禁止加入 Git、日志、文档、前端或上传包；忽略 `.env*`、`.vercel/`、`work/`。

## 风险与处理

首次玩家可能把反冲方向理解反：开局先显示向下水流与向上角色的演示箭头，第一平台足够宽。水量可能形成死局：可达性模拟验证平台间距，并提供一键回到补水检查点。触屏容易遮住角色：摇杆放在独立下部操作区。纯 2D 视觉缺少厚度：采用分层阴影、反冲姿态、前后景视差和结局拉远，而不是增加复杂引擎。
